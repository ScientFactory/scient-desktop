# Reusable document template

Deliver a Scient project skill with a design brief, a reference file or project-relative reference, a rendered reference PNG and a sample that demonstrates the design on new content.

1. **Inspect the reference.** Work from one .docx, .pptx or .xlsx. For a native Google file, use `google-workspace` to export the corresponding Office file and record its origin and any export differences. Inspect the Office structure with the format skill and render it in a fresh directory with the Document Lab runtime’s `doc.py render`. Open the images and choose a representative page, slide or sheet for the reference PNG. Done when the reusable structure and the visual baseline can both be located.
2. **Distill the design brief.** Record the named styles and hierarchy, fonts and sizes, palette, spacing, page or slide dimensions, margins, and common layouts. Identify which placeholders and examples should be replaced. For Word, capture page setup, sections, headers and footers. For PowerPoint, capture masters, layout roles and chart conventions. For Excel, capture tab roles, cell styles, number formats, formulas that should carry forward and print setup. Record any limits imposed by the reference, such as substituted fonts or Google export differences. Done when each rule is tied to a style, layout or visible example and a builder can distinguish reusable design from example content.
3. **Write the project skill.** Load `scient-skill-authoring` and use `<project>/.scient/skills/<name>/` in an initialized project with `.scient/project.json`. Choose a lowercase kebab-case name and match it to the folder. If that folder already exists, choose a different name unless the user asked for an update. Write `SKILL.md` with that `name`, a description that uses the intended request wording and names the nearest format skill, and ordered steps with checkable completion criteria. Put the design brief in the body or a linked reference. Save `SKILL.md` and its resources directly in the skill directory. The project loader allows up to 200 files, 5 MiB total and 1 MiB per file, including `SKILL.md`. It reserves `scient.skill.json`. If a reference would exceed a limit, bundle a smaller representative resource such as a trimmed sample or rendered PNG, or use a project-relative path to the original. Keep the reference PNG within the same limit. Tell future runs which format skill to use and where to replace content. Done when the design brief, reference and PNG resolve and the bundled files meet the catalog limits.
4. **Make and compare a sample.** Apply the new instructions to one sample with different content. Validate and render it through the format skill, with recalculation for Excel. Compare the sample to the reference render for typography, layout, palette and recurring elements, then check that the changed content fits and example data is gone. Update the design brief and rerun any failing checks. Done when the sample passes the format checks and the important design features match, with any exceptions recorded.
5. **Check the catalog and test discovery.** Find the new name in Scient Settings’ skill catalog.

   Exercise the saved skill with an explicit load, then try a fresh request for the reusable design without naming the skill. Try a nearby one-off formatting request that should select the format skill. Record catalog visibility, explicit load, automatic selection for each prompt, and sample fidelity as separate checks. Done when the catalog lists the target skill and the discovery checks have an observed result or a named gap.

6. **Deliver.** Link the project skill, reference PNG and sample. State which catalog, load, discovery and comparison checks ran and what each showed. Done when the user can locate the template and see the evidence for its fidelity.
