## Composition

### New T3 features

- **Agent feedback (#35871) stays off in Scient.** Its reports carry agent-written text, and
  optionally conversation text, through product analytics. Scient's analytics gateway does not
  accept that text and Scient's privacy page does not cover it. One gate
  (`scient/ScientAgentFeedbackGate.ts`) makes every effective server setting, including a managed
  lock and the unresolved-secret snapshot, read the mode as off, so agents get no feedback tools
  or instructions and the store refuses reports; the server does not advertise the capability, so
  Settings hides the Labs switch; the CLI `feedback` command is not registered. T3's code, schema
  and migration stay. Turning it on is the owner's decision (gateway contract, privacy text,
  Scient wording instead of "the T3 team"), tracked in #1078.
- **Durable workflows (#38882)** stay as T3 ships them: off by default (`workflowsEnabled`), no
  UI. T3's `t3_workflow` tool is `scient_workflow`; workflow calls to other machines, typed-step
  corrections (`scient_submit_output`) and the off message (no Settings switch, the Scient home)
  use Scient's names. Agents see the workflow tools as T3 lists them: the MCP tool list grows
  2,558 bytes (label `agent-context-increase`).
- **Milestone events (#40774)** are taken as shipped.

### Server and providers

- **Idle Codex threads (#41055).** T3 now keys idle unloads by native thread. Scient's earlier
  fallback for a thread unloaded on another instance (#30647) is kept, and is recorded only when
  the unloaded native thread is the current one; detach waits for every pending native thread of
  the app thread and for that current one.
- **Checkpoints (#41052, #41113).** T3's reusable checkpoint scope replaces Scient's cwd
  comparison, which fixed the same "moved to the project checkout" hold; Scient's run, node and
  provider-thread identity checks stay. Queued restores skip deleted threads.
- **Claude (#41086, #41120, #41085).** T3's program read and model-change restart wrap Scient's
  ownership checks in the start-query block.
- **Analytics (#35871).** `AnalyticsService.record` returns whether the event was queued;
  `ScientAnalytics` follows, and Scient's test doubles return `true`.
- **Feedback and workflow tools** need the provider session service for Scient's write-access
  check, as Scient's other write tools do.

### Desktop

- **Remote request headers (#41092).** Taken. T3 installs the policy for the newest main window
  only; Scient can have several windows, so older ones still send the desktop origin. A
  follow-up branch fixes this for every open window.

### Web

- **Large files (#40631).** T3's full-file streaming replaces Scient's large-text rule for drafts,
  Markdown, HTML and Mermaid source. Compute files, LaTeX, `.bib` and an active citation reveal
  keep the bounded source view (`keepsBoundedSourceView`), and PDF is excluded. The large-file
  bar offers Copy only: Scient's header already saves a copy of every file. T3 now renders an
  ordinary Markdown preview in pieces, where a footnote resolves only inside its own piece; a
  follow-up renders a footnoted file whole again.
- **New thread (#41070).** T3's flow opens the draft without waiting on `t3.json`; Scient's
  checks that guarded that wait are removed, and its navigation intent, carried-over content and
  project lookup fallback stay. As in T3, a workspace choice made while the file loads and then
  set back to the provisional value is replaced by the file's default.
- **Thinking under a streaming reply (#41060).** T3 drops the Thinking row as soon as a reply
  streams. Scient reveals a reply's lines after a short wait and `ThinkingRowFade` hides Thinking
  once they show, so Scient keeps the row until then; T3's mobile change is taken.
- **Sidebar (#33057).** The folder button picks or adds a project, with Scient's folder icon.
- **PR description links (#41073).** Scient's own file-link opener (`useChatFileLinkOpening.ts`)
  opens a path from Markdown rendered in another checkout under that checkout, with T3's test.
- **Linked computers (#41005).** T3's unlink confirmation is taken; a merged warning that named
  "T3 Code" names Scient.
- **Timestamps and language (#39494).** The formatter takes both new parameters; the i18n

## Review

An independent Codex review (GPT-6.2 Sol) found, and this alignment fixes, with tests: a saved or
managed agent feedback mode reached the live settings; the migration 059 ledger stopped at 111;
workflow corrections named `t3_submit_output`; and a handoff detach could skip the current native
thread's idle release. Its other findings are T3 behaviour recorded above (footnotes, a late
`t3.json` default) and the multi-window header follow-up.

Its re-check found, and this alignment fixes, with tests that fail without the fix: the gate ran
when normalizing a write, so a saved and locked mode rejected unrelated settings writes (the gate
now applies on reads only); analytics could still queue an `agent.feedback` event (Scient
analytics now refuses it); and an older idle timer could replace the remembered release of the
current native thread (each app thread now keeps every release). T3's workflow authoring skill in
`skills/` keeps T3's names: only T3's authoring eval uses it.

A second, narrow re-check found that a feedback report an earlier build queued could still leave
through the analytics worker (the outbox now drops it), and that the remembered releases had no
bound on a long-lived shared runtime (the 16 most recent are kept). Both are fixed with tests that
fail without the fix.
