## Composition

### Fresh sessions (#30323, #30325, #30326)

A message can start a fresh provider session in the same thread, without the thread's earlier
context. `/clear` arms it for the next message, and scheduled tasks can run in one thread with a
fresh session each run.

- **Composer:** `/clear` sits beside Scient's `/fork` in the slash menu. Scient's send flow arms
  it, passes `freshContext` to the turn plan and the turn start, and disarms it once the turn is
  accepted. Queue edits, extracted queue intents and direct prompts never arm it. Scient's own
  resume-compaction check also skips a fresh send (`472b2d3a26`, found in review), so a stale
  thread never compacts the conversation the fresh session drops.
- **Queue:** a queued fresh message keeps Scient's queue parts and uses T3's rule: it may skip
  compaction but never steers into a running turn.
- **Orchestrator:** T3's context boundary, provider-thread choice and steer refusals are taken.
  On Scient's same-provider path the session a fresh run releases joins Scient's own detach list,
  so one loop detaches every released session ("Started a fresh session.") and a released active
  session gets a new session ID. Scient's lazy history read for forks and imports applies only
  before the latest fresh boundary, like T3's legacy import read. Scient's held-Droid filter stays
  on the restart handoff.
- **Queued fresh runs:** Scient lets a queued run on the same provider resume the active native
  history. A fresh run never does (`e984025a76`); otherwise a fresh message queued behind a
  running turn carried the old conversation on (found live and by T3's provider-switch tests).
- **Scheduled tasks:** T3's thread mode and its settings merge as upstream.

### Threads

- **Side chats inherit the parent's permissions (#31114).** Scient's per-run runtime policy stays;
  the rule that forced a side chat's first turn to ask before acting is removed, as in T3.
- **Snoozing with a pending question (#20058).** Scient builds the thread shell in
  `@t3tools/shared/orchestrationV2ThreadShell`, so T3's ordering is ported there: an approval
  ranks before a question, and a waiting secret or link card shows over an older question but
  never over an approval.
- **Worktree branch changes (#31599)** and **divergence after a merged branch changes (#31342)**
  merge as upstream; Scient's runtime layer registers `WorktreeBranchSync`.

### Server and providers
