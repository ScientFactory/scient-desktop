## Working shelf and Sciant sections

Upstream's setting already decodes to `false`, so the beta ships off and users
opt in. Two composition points were required beyond the conflict resolution.

First, the toggle must not remove rows from Sections. Classification splits the
inbox into `active` and `working` whenever the setting is on, and that filtered
array was reaching `useSidebarSections`, which would have hidden busy threads from
their sections and given the remaining rows the beta's time ordering. A
`sectionInbox` array now records every inbox thread, and the Sections view
receives `sectionActiveThreads`, sorted normally and independent of the beta.

Second, user docs state that the shelf belongs to the default Pinned and Active
layout and that turning off **Group by section** is what enables it. The Settings
toggle is still visible when Sections is on, where it has no effect. The owner
gave an ambiguous approval to hide that control, so it was left as upstream ships
it and raised with them instead of guessed at.

## Open items for the owner

1. **`expo-modules-core@58.0.9` thread safety.** Every `@synchronized` block is
   gone from its iOS tree, 6 on 57.0.14 and 0 on 58.0.9. The repository's own
   ThreadSanitizer harnesses catch the resulting races in the permissions registry
   and the notification centre manager. This range moved Expo within 58 and did
   not restore them, so the two failures persist. Hosted CI stays green because
   both tests are `skipIf(platform !== "darwin")`. Restoring the locks in a
   `patches/` entry is the recommended fix and remains unstarted.
2. **`node-pty`.** `^1.1.0` versus `^1.2.0-beta.15` is still undecided; upstream's
   patch entry stays unmapped.
3. **Update-all scope.** The bulk action deliberately excludes Scient-managed
   runtimes. Whether it should also cover them, given their qualified lifecycle,
   is an open question this alignment did not decide.
4. **Pre-existing and still open:** `main` lacks
   `.github/workflows/release-desktop.yml` while
