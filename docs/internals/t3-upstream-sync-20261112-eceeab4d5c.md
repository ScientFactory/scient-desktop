## Continue threads after restarts

T3's default (on) replaces Scient's off. Scient shipped it off, so most people never chose it:
the first load of this version turns it on everywhere, including a machine or a project that had
it switched off. A record of that switch-on (`continueThreadsAfterServerUpdateTurnedOn`) is stored
next to any later "off", so a choice made afterwards is kept. A managed policy's own default still
decides. The settings file is rewritten at load only when a stored "off" was removed.
