## Composition

### Projects with several repositories (#35925)

- **Checkpoints and rewind.** T3's repository scopes, task-folder rollback and per-repository
  diffs are taken. Scient's root-scope workspace binding, Overleaf checkout barrier and
  `checkpointSupportsRewind` gate are mounted inside them; restore targets carry only `id` and
  `cwd`, so the root-scope match checks the folder. A "missing" checkpoint still allows a rewind of
  a linked project folder, and stale ref deletion stays limited to ready checkpoints. Diff
  baselines never cross workspace roots, as before.
- **Launch.** A plain project folder that tracks repositories now launches into T3's task folder;
  it reaches the project root only when there is no task-folder plan or the folder is itself a
  repository. Before, Scient sent every non-Git folder to the root, which would have switched the
  feature off.
- **Storage cleanup.** T3's task-folder removal, dangling-gitfile check and merged-in-a-fork lookup
  are taken, with Scient's archived and queued-run recheck, its one-argument local-changes and
  submodule checks, and Compute retention around task-folder removal. T3's `git clean -ffdx` stays
  out. An empty ignored folder no longer keeps a worktree: without that, a task folder's emptied
  build folders kept it forever. Automatic cleanup removes each task checkout through Scient's
  guarded path (`removeGuardedWorktree`: the Overleaf barrier held while the checkout is moved
  aside, re-checked and removed), so a late ignored file or an Overleaf sync landing during removal
  survives. A project with a teardown command keeps its task folders until the user removes them;
  automatic cleanup never runs that command. Explicit removal takes the task folder's lease and
  rereads its record, so it no longer races Add repository (an upstream race as well).
- **Rewind safety.** Each repository's pre-rewind snapshot, recovery registration and restore run
  inside one Overleaf barrier section, and undo restores go through the barrier too: a checkout the
  barrier refuses is never rewritten and keeps its recovery ref. A conversation-only rewind leaves
  task checkouts alone and rebuilds the task folder only when the provider's own working directory
  is gone; a file rewind refuses a shared task folder before rebuilding anything.
- **Web.** The rewind dialog offers "Revert repositories too" and keeps Scient's open-while-reverting
  behavior and its explanation when files can't be restored. `diffAvailable` combines Scient's
  project and server-thread guard with T3's tracked-repository conditions. Project settings show
  T3's Repositories section before Scient's Overleaf, browser profile and Skills sections.
- **Runtime policy.** T3's `workspace` (the folder list) joins Scient's runtime-policy schema in
  contracts, so stored provider work and held steers keep it, and passes through Scient's host-copy
  hooks to Claude, Codex, OpenCode and ACP. Oh My Pi gets the same folder list: the adapter writes
  it beside the session and refreshes it when a turn's folders change, and Scient's extension adds
  it to the prompt.
- **Docs.** `multi-repo-projects.md` names Scient and `scient project add`; `t3.json`, its keys and
  the `T3_WORKTREE_*` variables keep their names.
