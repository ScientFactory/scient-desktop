# T3 upstream alignment, 2026-11-24 (4ce9f8c1b8)

## Scope and history

This alignment integrates, in one literal merge, the 73 official commits after `4ce9f8c1b8`
through `364ca478682e25c6373c041dc5774d6b726b2c08`. No donor commit was replayed, squashed or
dropped. It stacks on the previous alignment (`4ce9f8c1b8`, Scient PR #1085).

T3 removes the changed-files card under assistant turns (#41317), settles a run when the provider
turn ends instead of after its checkpoint capture (#41362), runs preview pages in their own
JavaScript world (#41757), caps API request bodies at 1 MiB by default (#41747), and scopes CI
release credentials to the steps and jobs that use them (#41765, #41778). The rest is fixes: Stop
no longer ends a run as completed, folders whose name ends in a space work everywhere, Windows
system tools run by absolute path, link and guest codes need the access they hand out, setup
scripts run when a removed worktree is restored, and many Escape-key, Pi, Antigravity, OpenCode
and mobile fixes.

This record describes the committed integration, not delivery or release acceptance.

## Composition

- **Changed-files card (#41317)** is removed as T3 ships it. Scient keeps each turn's changed
  files per assistant message, which reply file links use; multi-window UI sync drops the card's
  expansion state. `turnDiffTree.ts` stays: T3 still ships it.
- **Runs settle before capture (#41362).** A completed run keeps Scient's queue clearing
  (`queuePosition: null`), and a fork still takes its source lock before its destination, after
  T3's wait for the latest capture. Scient's last-attempt capture settlement now also gives a
  completed run still awaiting capture its error checkpoint, so queued work is released when every
  capture attempt fails (the existing "fails on every attempt" queue test failed without it).
- **Preview pages in their own world (#41757).** The pick preload imports `ipcRenderer` for
  Scient's sign-in capture and login-form detection. The main process now runs the login-form
  report and fill scripts in Electron's preload world (999), where the preload keeps the login
  document state; in the page's world that state is no longer visible.
- **1 MiB API bodies (#41747).** Scient's multipart uploads declare their own totals and are
  unaffected. The middleware that read Word export bodies under a 12 MiB cap moves to
  `apps/server/src/scient/largeRequestBodies.ts` and also covers Save to Library, whose page
  metadata may exceed 1 MiB; its test now runs with T3's default.
- **Pi MCP aliases (#41779)** do not apply: Scient's Pi bridge registers no `mcp__t3_code__`
  aliases, so the Scient extension source and its test stay as they were.
- **Mobile workflows (#41765)** adopt T3's build/record split (`mobile-eas-*-build.yml`) with
  Scient's release gate, Expo project variables and GitHub-hosted runners carried into the new
  files. Scient keeps no version-override input, so T3's version job is dropped.
  `workflow-credentials.test.cjs` runs in CI; its three checks of jobs Scient does not have assert
  that those jobs stay absent. `release.yml` stays Scient's own.
- **Settlement reopening (#33995)** keeps Scient's fork-inherited message times.
- **Smaller compositions:** keyboard-opened context menus take T3's `source` argument before
  Scient's selection owner; Antigravity skill filters keep Scient's name prefix; Windows
  `schtasks` tests use T3's absolute path with Scient's task name; the PowerShell login timeout
  keeps Scient's 5 s on Windows; Git LFS objects publish after Scient's checkpoint witness.
- Branding: user-visible T3 names are Scient's (`scient_worktree_list`, `scient_thread_send`,
  the ssh askpass helpers, the OpenCode docs).
