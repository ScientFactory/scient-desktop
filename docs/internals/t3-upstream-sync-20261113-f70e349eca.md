Each failure after the merge was read as a question of alignment first: take T3's code where it
now does the job, make Scient's difference smaller, and keep tests at the right level without
repeats.

- **Deeply nested tool rows:** T3's export now tolerates a row nested past SQLite's JSON limit;
  Scient's history query turned such a row into `null`, so the export failed. The query now
  passes it through, and a malformed row still fails at decode.

  new message through instead of replacing it with a generic one.

  scan reply, whose command and skill lists the server always leaves out, so the scan never

  T3's does; a full inventory reply keeps its own provenance. Reading the code, the same mismatch
  also kept a project's own skills and commands from reaching the composer on main; that was not
  checked live.
- **Model fallback:** T3's new pick from the raw model list (#24110) is skipped for Pi, Oh My Pi
  and Scient Agent, which pick only from the models they show.
- **Tests:** Scient tests take T3's new fields and labels, its per-prompt Pi acknowledgement, its
