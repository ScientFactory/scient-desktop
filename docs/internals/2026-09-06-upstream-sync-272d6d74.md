### Approved onboarding decision

Scient's local setup is not replaced by T3's generic install-terminal wizard. Local first-run
rendering bypasses that second gate, and direct local `/welcome` visits use Scient's existing manual
setup route. Hosted clients retain upstream connection onboarding.

Both local import entry points mount one shared `ProjectImportStep` only after a click. The new
Scient wrapper supplies the primary machine, existing operate access, a scrollable dialog, and
normal project navigation. It does not invent another scanner/import service or change provider
installation or sign-in.

The active onboarding gate must survive the first project arriving while its conversations are
still being imported. A presentation-local latch preserves that ownership; durable completion and
dismissal still win, and a subsequent launch with existing work skips setup. Cancelling import
alone does not complete onboarding. The dialog prevents dismissal during commands, but a delayed
shell snapshot after those commands finish does not trap the user. Navigation failure retains
imported work and offers recovery.

The component extraction is shared with T3's hosted wizard rather than a second implementation.
The production web build emits a separate import chunk. The onboarding seam manifest and
[maintainer guide](scient-onboarding.md) record the local mounts. The
[user guide](../user/welcome-wizard.md) states supported sources, history limits, omitted
attachments/tool activity, and retry behavior.
