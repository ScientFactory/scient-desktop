## Composition

- **Effect 4.0.5 → 4.1.2 (#26833, #29780).** This change accounts for 81 of the 123 conflicts.
  - **New crypto services.** `effect/Crypto` is split into `effect/crypto/SecureRandom` and
    `effect/crypto/Digest`. Node's crypto now needs `NodeCrypto.layer` beside `NodeServices.layer`.
    Scient-only code and tests use T3's patterns throughout. A file that also imports `node:crypto`
    names the Effect module `NodePlatformCrypto`.
  - **Other renames.** `randomUUIDv7` is now `uuidV7`, `NodeSocket` is now `NodeWS`, and command
    arguments and environment values may now be `Redacted`.
  - **Batch insert.** The Analysis run index now inserts in non-empty batches with
    `Array.chunksOf`, which the stricter batch-insert type requires.
  - **Document tools.** They declare `Digest` beside `SecureRandom`, because the old single service
    covered both.
  - **Versions and lockfile.** Scient's Effect and alchemy pins equalled T3's old ones, so T3's new
    pins apply as they are. The lockfile was regenerated from main's: `hasBin` markers went from 125
    to 126, with none lost; the new one is `@alchemy.run/test`. T3's follow-up #29780 keeps the
    packaged server's bytecode cache working after the upgrade.
- **Kiro (#14693, #28253).**
  - **Off by default.** T3 ships Kiro off and Scient keeps it off, by the owner's decision. Scient
    adds no managed runtime or assisted setup for it.
  - **Scient instructions.** Kiro gets Scient's instructions through the ACP prompt bridge, as fx
    does. Otherwise it would receive T3's text.
  - **Tool-call titles.** Kiro titles tool calls `@<server>/<tool>`. Scient presents its tool server
    to these agents as `scient`, so one shared pattern now accepts both `t3-code` and `scient` in the
    title, suffix, meta, goose and `mcp__` checks. Without this, #28253 would compile and do nothing.
  - **Lists and wording.** Kiro sorts after fx. Scient's own metadata decides provider badges, so
    Kiro's "Early Access" badge isn't shown and only Muse keeps "Beta". User text says Scient.
- **Shared ACP code.** The rules for writing a session's config options now compose with Kiro's
  late-update counter:
  - T3's counter replaces Scient's comparison of object identity for plain writes.
  - Confirmed writes keep Scient's ordering.
  - Droid's model corrections also apply to T3's new change stream.
  - Native compaction marks the turn as started first.
- **Forks from an earlier turn (Scient bug found by T3's Kiro test).** Scient's frozen fork start
  gave the agent only the turns up to the fork point. ACP providers, and Pi (by reading the code),
  read "no later turn" as "the latest turn" and copied the whole session. The fork start now passes
  the source's later turns from the live projection, and falls back to the frozen turns if the
  source can't be read. A unit test covers this.
- **Claude.**
  - **SDK.** Claude Agent SDK 0.3.276 → 0.3.284 (#27577) keeps compaction across forks.
  - **Updates (#27958).** A Claude the user installed updates through the npm, Homebrew or native
    release feed. Scient's managed Claude stays manual-only.
  - **Subagents (#28356).** Subagents left by a stopped process now end, through T3's shared helper,
    which keeps Scient's owner checks.
  - **Imported sessions.** They resume on their first turn (#23219), and session scans survive an
    unreadable `.git/config` (#23690).
- **Provider switch (#23198).** Detaching the previous session reuses Scient's existing switch plan.
  A restart now also triggers when attachments need one.
- **Migration.** T3's `078_DropOrchestrationEventCorrelationIndex` lands as Scient migration 82,
  because Scient already uses 78–81. Nothing in Scient filters by `correlation_id`.
- **Relay text (#27660).** Scient's wording stays. T3's real improvement merged in `CloudLink.ts`:
  a stale "not linked" result is dropped once the tunnel config is stored. Remaining
  "T3 Connect" reasons in `ConnectReachability.ts` now say "the relay".
