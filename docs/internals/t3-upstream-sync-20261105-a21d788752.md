## Composition

### Typecheck tooling (#31028)

Every package now typechecks with `effect-tsgo tsrs --noEmit`, the Rust TypeScript checker with
Effect's diagnostics built in, and the `typescript` catalog entry is gone. Scient's own packages
(`scient-*`, `effect-omp-rpc`) use the same command. Effect's diagnostics now fail the build, so:

- `JSON.stringify` inside Effect code carries T3's `globalJsonInEffect:off` directive where Scient
  already suppressed the old rule (Droid custom models, the Oh My Pi bootstrap, the Overleaf
  packaging probe);
- one `Effect.runPromiseExit` inside an Effect in `WorkspaceFileMutations` reuses the file's
  existing context runner;
- 36 `effectSucceedWithVoid:off` directives that no longer apply are removed;
- one Scient test builds a real `BearerConnectionTarget`, as T3's tests now do.

### Signing through Effect (#30474, #30501, #30523, #30529, #30540)

T3 replaced `jose` and `node:crypto` signing with `effect/jose` and `effect/crypto`, and moved
asset signing behind an `AssetSigner` service. Scient follows:

- Scient's document tools (`scient_pdf_build`, `scient_document_export`) get `AssetSigner` from
  their toolkit layer, as T3's attachment tools do.
- Conversation-import upload URLs sign through `AssetSigner`. The key (`asset-access-signing-key`)
  and the format (unpadded base64url HMAC-SHA256) are unchanged, so URLs issued before the update
  still verify.
- Scient test harnesses provide `AssetSigner.layer` and `EnvironmentKeys.layer` the way T3's do.
- The server no longer depends on `jose`.

### Secrets (#30256, #30257)

Agents open the secret card instead of asking in chat. A secret the user already pasted can be
saved to a private file for a command or child without a card. After a decline, agents are told
not to ask again. The tool is always loaded for Claude. Scient's `request_secret` merges into this
unchanged; only its test mocks gained T3's `savePasted`.

### MCP Apps from Claude tool calls (#29803)

T3 renders MCP Apps that Claude's tool calls return. T3 skips its own server by its
`mcp__t3-code__` prefix; Scient's server is `scient`, so the check is `mcp__scient__`, and Scient's
own tools are never shown as MCP Apps. The new `packages/shared/src/mcpApp.ts` is classified in
`scient-extensions-seams.json` as upstream-owned and unchanged.

### Providers

- **Claude:** the models Claude Code reports (#30511) now come together with Scient's reloaded
  skills and its CLI sign-in check. The context meter reads the window Claude reports for models
  outside the catalog (#30051). The Claude Agent SDK moves to `^0.3.316`.
- **Codex:** forking a thread archived elsewhere retries after unarchiving (#29618). Scient's rule
  that a session without MCP injection forks without a credential stays inside that request. Dev
  servers a Codex agent starts show under its thread (#29687).
- **Pi:** T3 merged Scient's stop-order fix (#30025). Scient's duplicate in `rpc.ts` is removed.
- **OpenCode:** `~/` executable paths are expanded before Scient's adapter is created (#29326).
- **Provider refresh (#29894):** realigned to T3's instance-based refresh, which ignores a probe
  from an instance replaced mid-refresh. Scient's account-change refresh
  (`ScientProviderReload.ts`) follows the same rule: when the instance was replaced, it refreshes
  the new one instead of saving the stale result.
