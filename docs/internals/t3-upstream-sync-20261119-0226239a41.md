## Composition

### Orchestration and providers

- **Released sessions leave memory (#39049).** Scient's session open path makes its own session
  scope; the event pump now stops when that scope closes, as T3's does.
- **Antigravity background commands (#38864, #38916).** T3's post-settle continuation,
  outliving-command tracking and settled-interrupt rules replace Scient's
  `extractBackgroundTaskId` for Antigravity. Scient keeps `terminateRuntimeProcessGroupOnInterrupt`:
  Stop ends Antigravity's whole process group, commands included, without `session/cancel`.
- **ACP adapter.** T3's negotiated flags, detached-request wake and outliving subagents sit beside
  Scient's `continuationSilence` (Droid only); each condition admits both. A Scient settlement rule
  that never let idle-on-completion subagents block a turn is gone: T3's own early return covers it
  and keeps its exception for subagents that outlive the prompt.
- **ACP termination (#23654).** The callback now runs once inside `recordTermination`, with the
  process's stderr; Scient still runs it in the caller's scope so a removal that waits on teardown
  cannot deadlock the reader.
- **Antigravity stderr (#23654).** Harness-failure log lines end the turn so a follow-up starts a
  fresh process; Scient keeps failing a malformed or oversized sign-in marker.
- **Antigravity plugin skills (#38960).** The instance profile's `config/plugins` is scanned with
  Scient's manifest namespaces and skips plugins `config.json` turns off. The scan also skips
  non-folder entries such as `.DS_Store`, which used to fail the whole skill lookup.
- **Unread Claude steers (#39018).** Steers are offered with priority `next`. Scient keeps an
  exiting query reserved until its cleanup ends, so a reserved query counts as gone when deciding
  that an unread steer stays pending. The orchestrator requeues it after Scient's terminal queue
  hold, so the requeued run is created already held.
- **Resume with a handoff (#38847)** uses Scient's prepared text for its fallback prompt.
- **Busy-source native forks (#23239)** sit beside Scient's frozen forks; a bounded portable fork
  still reads the parent's history by run id and leaves rolled-back runs out.
- **Workspace snapshots.** T3's merge of provider-reported and registry-scanned folders applies
  only within one native inventory generation, as Scient's rule required.

### Server, cloud and SSH

- **Relay configuration scope (#37823, #38892).** Setting up or replacing a Scient Connect link
  needs `relay:configure`. Scient's desktop sign-in still moves a computer to its account
  (`replaceLinkedAccount`) after T3's revoked-link replacement, and a computer turned off in
  Scient Connect still takes no late link.
- **SSH aliases (#38852).** Workspace binding evidence keys a remote through the same
  `ssh -G` alias resolution as the project identity, so the two keys still match.
- **CLI through the running server (#38991).** Its session is labelled `scient cli`.
- **Settings watcher (#39056).** Scient's watcher, which reads file metadata, stays; T3's
  `watchLinkTargetChanges` is not used. T3's directory-replacement tests pass on Scient's watcher;
  its registration-race test, which depends on T3's watcher internals, is not carried.
- **Antigravity install on Windows (#29279).** Scient's installer filesystem already retries
  `EPERM`, `EACCES` and `EBUSY` renames for up to 15 seconds; T3's
  `retryWhileWindowsHoldsHandles` is not used.
