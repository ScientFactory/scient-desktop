## Composition

### Voice (dormant)

T3 added its own local dictation: a transcribe.cpp engine on the server (#30625), opt-in
environment dictation on web, desktop annotations and mobile (#30623, #30624, #31059), and
transcript cleanup through a text model. Scient keeps its own voice as the only one users see
until the owner decides how the two relate:

- **Server:** T3's speech service, routes and model catalog merge as upstream and stay idle; they
  load nothing until asked. The environment reports no voice transcription
  (`SCIENT_T3_VOICE_TRANSCRIPTION` in `ServerEnvironment.ts`), so every client hides T3's
  microphone, setup dialog and pills.
- **Settings:** T3's `VoiceSettingsPanel.tsx` stays byte-identical to T3. Scient's page moved to
  `apps/web/src/scient/voice/ScientVoiceSettingsPanel.tsx`, and the voice route shows it. T3's
  voice search entries are hidden; Scient's "Voice models" entry stays.
- **Shortcut:** T3 binds dictation to mod+shift+d, which Scient uses for Duplicate tab. While T3
  voice is dormant, dictation has no default shortcut.
- **Composer and comments:** Scient's microphone control stays. T3's controls sit inside the
  primary actions and never show. The citation comment editor keeps Scient's version, which only
  accepts T3's voice-setup prop.
- **Transcript cleanup:** Scient's own providers (Droid, Antigravity, OMP, Scient Agent) report
  it unsupported; Scient's Muse and native-lifetime wrappers pass it through.
- **Left for the voice decision:** Shortcuts lists T3's dictation command with no key, and T3's
  `docs/user/voice-input.md` is branded Scient but not linked.
- **Dependencies:** `transcribe-cpp` 0.4.1 and `@handy-computer/models` 0.2.3 ship with the server.
  Scient's macOS and Linux packages unpack transcribe.cpp's native libraries beside Scient's
  compute bridge.

### Provider write batching (#31656)

T3 batches a run's queued provider writes into one transaction and publishes after the commit.
Scient's run loop keeps its own per-event body (running-fork text capture, workflow ownership
transfer, Codex window records) and now runs through T3's batch consumer. The consumer is generic
in its event type, so Scient's running-fork text batches share the stream and never batch.
Scient's commit order (`scient-fork/CommitPublication.ts`) stays the commit step; inside a batch a
write joins the batch's transaction and publishes after it, as in T3.

### Secrets (#31670, #31651, #31652, #31653, #31646)

the resolved key. On mobile, Scient's one-tap sign-in code field stays beside T3's provider
choice.
