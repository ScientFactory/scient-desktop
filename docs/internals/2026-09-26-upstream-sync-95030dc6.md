## Decisions

**Client-side queued messages — Scient-owned policy retained.** Upstream commit
`295d7cba09` fixes the queued-messages feature. Scient reverted that feature
deliberately in `a7da056116` (2026-09-15), and the revert is total. That commit
is the _only_ upstream change in this range to `ChatView.tsx`,
`MessagesTimeline.tsx`, or `MessagesTimeline.logic.test.ts`, so preserving the
revert is a clean cut. Removed together, because keeping any part would leave a
dangling reference: `queuedMessageStore.ts` and its test, the new
`QueuedMessageSender.tsx` and test, `chat/sendQueuedMessage.ts`, the
`__root.tsx` mount, and the `readThread` helper in `state/entities.ts` (used only
by those files). The four conflicted files keep the owned side.

**node-pty stays on `^1.1.0`.** Upstream moves to `^1.2.0-beta.15` for a
linux-arm64 prebuild. Scient publishes `desktop_linux_arm64` as an AppImage built
on arm64 hardware, so it does not consume that prebuild, and a pre-release
native dependency on a shipped target is a supply-chain decision for the owner.
Reported, not adopted. One line to change if wanted.

**Usage page Spend metric preserved.** Upstream moved the metric list to
`usageShortcuts.ts` and gave every entry a keybinding command. Scient's `spend`
metric drives `includeAccounting` for the usage-accounting feature and has no
command. The composed file keeps one canonical imported list and appends the
Spend entry locally, and `shortcutTitle` renders a shortcut only for options
that have a command.

**`http.ts` keeps Scient's asset route.** Upstream added
`untracedRequestsLayer` (the renderer trace proxy no longer tracing itself) and
re-registered the asset route for `GET` only, inlined. Taking that side would
have produced a duplicate `assetRouteLayer` binding and lost HEAD and 405
handling. The composed file exports the new layer and keeps the owned route.

**Keybindings contract is additive.** Seven new command literals, no removals.
`KeybindingCommand` remains a closed literal union, so a client older than these
commands cannot decode a settings blob that names them. Standard for this
contract, noted for skew review.

## Defect found and fixed in upstream code

**`ProjectionSnapshotQuery`'s new unsettled filter broke a fork helper.**
Upstream added a `settled` filter and, in doing so, changed one query from
`FROM projection_threads` to `FROM projection_threads threads`. Scient's
`completedAnswerSql` correlates on `projection_threads.thread_id` by table name.
With the alias, that reference is invalid and every statement using the query
failed to prepare with `SQLITE(1) SQL logic error`. Git raised no conflict:
the helper is not a conflicted file.

Fixed by keeping the filter fragment unqualified (it is spliced into queries both
with and without the alias, and no joined table carries `settled_at` or
`settled_override`, so unqualified resolution is unambiguous) and restoring the
unaliased `FROM` on the one query that uses the helper. This took the server
suite from 33 failing tests to 2.

### Failing tests, reported honestly

`src/bin.test.ts` (10), `src/cli/pair.test.ts` (1) and `src/server.test.ts` (27)
fail for the established reason: they require external Clerk and cloud fixtures
that are not available locally. This is the same set, and the same count, that
the owned base produces. Hosted CI is the authority for this group.

The following new upstream/CI issues were found during review and corrected
without weakening the assertions or the product boundaries:

1. `ThreadSettlementReactor.test.ts` — the new comparison fixture inherited
   Scient's default opt-out for automatic merge settlement while asserting the
   opt-in behavior. The fixture now enables `sidebarAutoSettleOnMerge`; the
   reactor and query implementation were unchanged.
2. `ProviderService.test.ts` — an oversized image path was appended to the
   prompt before the size check, so the later total-limit guard rejected a
   native image that should still be deliverable. Context appending is now
   transactional: an optional image path is omitted when it cannot fit, while
   generic files and captured-window accessibility context still fail closed.
3. `packages/client-runtime/src/platform/persistence.test.ts` — the 1,000-case
   generated round-trip property test timed out at five seconds only under the
   parallel Workspaces CI job, although it passed in isolation. It now uses 256
   generated cases, still exercises the same schema round-trip assertion, and
   passes in isolation in under one second. The hosted CI rerun remains the
   final authority for resource contention.

No gate was weakened or skipped to conceal a product failure.
