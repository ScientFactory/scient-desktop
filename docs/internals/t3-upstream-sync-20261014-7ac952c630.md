## Integrated behavior and composition

The range is mostly reliability and performance work: SQLite reader and
checkpoint workers, uncached large-parameter statements, one database owner per
data directory, update-all restart and background-work fixes, Claude, Codex,
ACP, Cursor and OpenCode provider fixes, full-screen HTML replies, coalesced
worktree cleanup sweeps, subagent prompt de-duplication in the event store, live
reasoning follow inside the reasoning box, pull-request link events, SSH and
terminal fixes, Effect 4.0.4 and tsc-rs 0.7.0.

Meaningful compositions (owner defaults where upstream and Scient policy differ):

- **SQLite.** Scient keeps `synchronous=FULL` and adds `checkpoint_fullfsync` on
  the writer and checkpoint worker. Upstream's reader and checkpoint workers run
  inside Scient's `makeWithDatabase`; both stop before the writer closes. Workers
  are opt-in, so the Overleaf state store's separate lease file (catch-up #536)
  keeps its own `busyTimeout`/`disableWAL` open path without workers.
- **One database owner.** Adopted across server, desktop backend pool, WSL backend
  and service launcher. On Windows, legacy owner records are checked against the
  process creation time through CIM with a 5 s timeout. Upstream's `Get-Process`
  cannot read SYSTEM or elevated processes, so a stale record whose PID was reused
  by one would refuse startup until reboot. A deciding test fails without the
  change.
- **Storage cleanup.** Archived-thread and queued-run (`presentQueuedRunsAsBusy`)
  protection stays in both the sweep read and the per-worktree recheck while
  adopting the reader worker and coalesced sweeps.
- **Event store.** Upstream `$.promptSequence` de-duplication composes with
  Scient's `turnItemMetadataSql`, revision stamps and transactions; replay and size
  estimates restore prompts before Scient's turn-item transform.
- **Session lifecycle.** Upstream 519d64f6c roster clearing on release is ported
  into Scient's retirement steps. `writeIfProviderThreadUnchanged` publishes
  through Scient's `commitAndPublish`. Run status and `queueHeld` are not written.
- **Restart continuation and update authority.** Update authority covers only
  unfinished runs. Settled runs whose background work was cut follow each
  project's continuation preference. A user Stop also blocks continuations from
  such settled runs; a deciding test fails without the guard.
- **Claude.** Live `applyFlagSettings` effort changes keep a Scient restart
  fallback for older CLIs. Probes run in the state directory. Start, query and
  task-owner identity checks remain in order after the native Stop wait.
- **Agent processes** stay under Scient's memory-limited `app-scient-agents`
  slice.
- **Text-generation fallback** (upstream #19386) is routed by exact provider
  instance ID.
- **Projection.** Timestamp `json_set` partial updates preserve Scient fields; the
  new `thread.pull-request-link-updated` event is handled by SQL and in-memory
  projections, client runtime, settlement, sync reactor and relay.
- **Update all** keeps Scient's Stable/Beta channels, the single installer owner
  (`installDesktopUpdateNow`), retired npm release polling, Scient skip-reason
  wording and the label-sized pill from Scient PR #564.
- **Full-screen HTML replies** keep a marked "Open in panel" action, so view
  source and Save stay reachable. Scient rich fences are unaffected.
- **Composer citations.** Upstream's citation-draft save on question or approval
  swaps uses Scient's `ComposerCitation` helpers, so file quotes keep their fields.
- **Effect 4.0.4.** `crypto.randomUUIDv4`/`v7` property uses across Scient files
  were converted to calls; no property-style production use remains.
- **Holds.** `NightlyMobileBeta.tsx` stays deleted. T3 Connect and other cloud
  surfaces stay behind Scient's disabled cloud identity. CONTRIBUTING, branding,
  provider order and publication holds are unchanged.

## Review and qualification evidence

Two independent source reviews ran on a different provider (Codex
`gpt-6.1-sol`, extra-high reasoning) against `d1db50fa98`: one for server,
persistence, orchestration, providers and desktop backend, one for web, desktop
updates, mobile, contracts and docs. Each explicitly assessed every listed
composition.

Findings introduced by the merge, both fixed in `06c097d29d`:

- The imported mobile test `environmentStatusText.test.ts` expected
  "Update T3 Code on Studio Mac"; the shared helper correctly says Scient.
- The adopted citation-save path lacked paired `SCIENT-FORK` markers.

Findings retained from the owned base, not introduced by this range, recorded as
follow-ups rather than changed in the alignment:

- Storage cleanup's final recheck precedes asynchronous Git work without holding
  the workspace lease that run admission would need, so work queued in that window
  can lose its checkout.
- During a local desktop download, update-all recomputes remote eligibility
  against the running app version and can skip confirmed remote targets.
- `docs/user/updating.md` says Linux updates need an AppImage; `.deb` installs are
  also supported.
- `OverleafStateStore.test.ts` (from #536) unlinks an open lease database; Windows
  refuses with `EBUSY`, so that case fails on Windows before reaching its
  replacement check. Hosted Linux CI is unaffected.
- Risk: if the Windows CIM query fails, a reused live PID is still treated as the
  legacy owner. This is conservative upstream behavior and needs a clearer
  diagnostic.

A third Codex review covered the owned-main catch-up `fa40302bd3` against both
parents. It found no composition regression and corrected two receipt facts (the
target tag and the 52nd unmerged path).
