## Integrated upstream behavior

### Reliability and orchestration

- Review diff previews preserve racy same-size Git edits by aging the copied
  index timestamp before the temporary Git index is used. Existing split-index
  and source-index preservation tests remain, with the upstream fractional-
  timestamp cases added.
- ACP late tool-progress updates no longer split a single assistant answer into
  multiple answer segments. The recent-tool-call set is bounded.
- Streamed Markdown holds a section title until its following block has content,
  avoiding a title that is briefly rendered without its section.
- Upstream Antigravity Stop handling closes an idle session with promoted
  background commands so those commands cannot outlive the turn.
- The per-thread automatic-settlement opt-out is integrated end to end:
  orchestration command/event contracts, persistence, server projection,
  client runtime, and web/mobile/desktop thread menus. The choice is independent
  of manual settle/unsettle and is version-skew gated.
- The upstream shell-code action is composed into Scient's existing rich
  Markdown/code-block surface. It only appears for a complete, closed shell
  language fence, rejects control/invisible formatting characters, and routes
  through the existing project-script execution path rather than introducing a
  second terminal authority.

### Providers and model compatibility

- The shared reset-credit coordinator now serializes account-level redemption
  and preserves idempotency across Codex and Claude. Codex keeps its bounded
  request and only reports an unconfirmed refresh for an actual reset.
- Claude banked reset credits are available only where the Claude OAuth login
  can be read; the implementation explicitly does not claim macOS Keychain
  support. Subscription, Bedrock/API, cooldown, rate-limit, and idempotency
  paths are covered.
- Codex protocol generation is updated for Effect `rc.115`, and the provider
  floor is advanced to Codex `0.156`. The compatibility manifest records
  `>=0.156.0` as supported, `>=0.149.0 <0.156.0` as unsupported, and older
  versions as broken.
- Antigravity Windows runtime unpacking now uses a short, instance-scoped temp
  root beside the profile. Existing Scient plugin projection and skill-link
  behavior remains intact.

### Desktop, cloud, and OTel composition

- Desktop update installs write a short-lived restart marker before stopping
  backends. The server consumes a fresh marker while preserving a managed
  tunnel across an update restart; failed or interrupted installs remove it,
  and stale markers cannot retain a tunnel.
- The marker mechanism is state-root scoped and does not activate cloud,
  signing, updater-channel, or publication authority.
- Malformed `OTEL_RESOURCE_ATTRIBUTES` no longer prevents startup. Valid
  attributes are decoded once and supplied to exporters; malformed values are
  omitted with a warning.
- Scient's fail-closed desktop safety envelope remains authoritative in the
  early-return branch, including the new resource-attribute shape. No invalid
  resource value can re-enable outbound telemetry.
- The existing Scient-owned release, signing, mobile-publication, and provider
  lifecycle boundaries remain unchanged.

### Web and presentation composition

- Upstream theme-token and lint improvements are applied to upstream-touched
  host files. Existing Scient-owned scientific and presentation surfaces are
  covered by an explicit, documented legacy lint boundary rather than being
  rewritten wholesale during this upstream sync.
- The shared Select control receives a semantic content-width variant instead
  of an application-level class escape hatch.
- The Sidebar trigger receives a stage-aware focus-ring variant, preserving
  Scient's stage artwork while keeping UI component ownership intact.
- Upstream Antigravity icon data and Computer Use icon are adopted while
  Scient's OpenRouter, Droid, OpenCode, and other product icons remain.
- Scient's custom stage artwork, scientific typography, provider settings,
  Sources/PDF/LaTeX/Markdown surfaces, project initialization, and release-note
  presentation remain authoritative.

## Conflict and semantic review decisions

The 36 conflict paths were resolved by category rather than by accepting an
entire side blindly:

- **Persistence:** upstream migration `54` was renumbered to Scient migration
  `57`; IDs 41–56 remain immutable. Migration manifests, compatibility tests,
  and the new column test were updated together.
- **Provider lifecycle:** the new shared reset-credit service replaced the old
  Codex-only service at the runtime composition seam; Claude account paths and
  existing managed/external provider behavior were retained.
- **OTel/cloud:** both upstream additions were composed with Scient's safety
  early returns and fail-closed envelope. Missing resource attributes in the
  safety branch and missing update-test marker plumbing were found during
  review and corrected.
- **Web host UI:** current Scient settings/provider/queue/scientific surfaces
  were retained where upstream's broad refactors would have removed owned
  features. Upstream navigation tracking, code-block execution, theme-token
  mechanics, and icon updates were added at narrow seams.
- **Shared code-block UI:** the upstream run action was adapted into Scient's
  existing `CodeBlockActions`/`MarkdownCodeBlock` components, avoiding a second
  code-block implementation.
- **Quality policy:** upstream's new shadcn checks remain enabled for the
  upstream-touched host. A measured legacy list preserves intentional Scient
  scientific/presentation CSS and type scales; this is recorded as a follow-up
  boundary, not hidden by disabling lint globally.
- **Tests and generated inputs:** the Codex generated schema was taken from the
  composed upstream source, while migration and provider test fixtures were
  updated to reflect the renumbered migration and shared coordinator.

The complete staged diff was audited for conflict markers, stale imports,
duplicate implementations, accidental product-language changes, and generated
input consistency. `git diff --check` and formatting checks are clean.
