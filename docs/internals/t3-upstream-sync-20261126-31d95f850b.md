# T3 upstream alignment, 2026-11-26 (31d95f850b)

## Scope and history

This alignment integrates, in one literal merge, the 251 official commits after `31d95f850b`
through `6d21ad2b25075b8246120aba5d478ba946a44fa8`. No donor commit was replayed, squashed or
dropped. Scient PR #1131.

T3's range is mostly fixes. The larger pieces are:

- Deleting a thread now erases its conversation, and threads deleted before the upgrade are erased
  soon after startup (#42119, #42814).

  PostHog naming is gone (#43099).
- Permissions: agents below Full access ask before a push runs repository hooks (#42535), and only
  a full-access MCP caller picks a delegated agent's own mode (#39489).
- Serving: HTML previews load files from their own folder only (#43042), and asset sandboxes
  follow the served type (#42999).
- A shared tooltip for the whole app (#42671).
- Cmd+K thread actions (#40742), dragging the sidebar away (#29546), and quoted-phrase search
  (#37700).
- Browser panel camera and microphone prompts (#38146).
- Workflow questions with described choices, reasons and links; withdrawing a question; named
  pools; run subjects (#42515, #42506, #42518, #42517).
- Antigravity's usage meter is removed, because it read Google's internal APIs (#43026).
- Database migration progress at startup (#37209).
- About 60 attachment-text, preview and terminal fixes.

This record describes the committed integration, not delivery or release acceptance.

## Composition

- **Deleted-thread purge (#42119, #42814):**
  - Side chats are T3 run forks, so T3's own rule keeps their source.
  - A Scient fork shows its source's items by reference (`scient_fork_history`), so
    `scient-fork/DeletedThreadPurge.ts` adds that edge to the purge's "still shown" and "released"
    recursions.
  - A deleted fork's frozen copies (`scient_fork_frozen_items`) are erased with it.
  - A thread a saved handoff still reads keeps its content: a per-item source without a frozen
    body, the fork view of such an item, and a range's fork view, together with the sources that
    view shows. Nothing records when such a reader is done, so this is conservative.
  - Scient's thread-file release runs before T3's purge. Queued prompts (`scient_thread_queue`)
    are not purged.
- **Migrations:** T3's 117–119 are Scient's 121–123, and the compatibility ledger lists them.
- **Delegation rule (#39489):** the caller's mode comes from the Scient agent session's live
  invocation policy, the same value Scient already ranks modes by. The refusal names Scient.
- **Push-hook approval (#42535):** T3 recognises its own MCP requests by server name. Scient's
  servers are `scient` and `scient-direct`, so the Claude and Codex constants name them; otherwise
  the new asks would never match in Scient.
- **Asset serving (#42999):** one MIME type decides the Content-Type and the sandbox, as T3 has it.
  Scient keeps `no-store` and `Vary: Origin`. Scient's document resolver already served only files
  below its base.
- **Claude adapter:** Scient's turn-start code carries T3's Auto fallback notices (#43162), MCP app
  context restore (#43008) and forked-skill transcripts (#43023). T3's Auto tool-ask change
  (#43035) replaces a Scient test that expected no permission callback in Auto.
- **Antigravity (#43026):** the usage probe is removed as T3 did. The driver keeps the HTTP client
  that Scient's Marketplace plugin actions use. `@napi-rs/keyring` stays a server dependency for
  Scient Accounts.
- **Web:**
  - T3's shared tooltip replaces the per-row providers everywhere, with Scient's props and copy
    inside it. Scient's sidebar tooltips take the shared 600 ms delay.
  - Cmd+K thread actions list Scient's menu items too; the section picker needs an anchor, so it is
    left out there.
  - The prompt stash refuses a new prompt when full, as T3 does, across Scient's shared-window
    store. Recovery of queued edits left by older builds offers the rest once the Stash has room.
  - Scient's citation voice control replaces T3's dictation hand-off (#42856); T3's tests of that
    hand-off are removed.
- **Files panel:** Scient's lazy tree replaced T3's `useDirectoryEntries`. T3's single-folder
  chain fix (#43018) is for merged folder rows, which Scient's tree turns off, so `onlyChildren`
  stays as T3 ships it, with a knip exception. T3's Refresh change (#42870) is ported to the lazy
  tree in a separate fix.
- **Copy:** T3's new startup page, pairing hint, push-hook refusal, managed-prefix error,
  camera/microphone prompts and Claude Auto docs name Scient. The workflow docs keep the `T3`
  workflow API name; it has brand allowlist entries.
- **Release:** Scient's single-job release needs no hidden-manifest staging (#42806). A missing
  `.vite/manifest.json` only turns off immutable caching.
- **Tests:**
  - T3's new tests use Scient's names: `scient_*` tools and Scient copy.
  - T3's new add-surface, minimap, tooltip-scroll and PR code-tab tests switch off Scient's
    surfaces or set sizes inline, because Scient's Tailwind does not scan test files.
  - Scient's deletion tests expect T3's purge, which also drops the settled effects before it.
  - Several Scient tests take T3's new props.
- **Agent context:** the MCP tool list grows 226 bytes, from T3's workflow subject and withdraw
  text (`agent-context-increase`).
