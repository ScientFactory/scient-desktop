## Composition

- **Forge refactor:** Scient's pull request, media and source-control code is
  ported to forge definitions and per-forge drivers; `SourceControlDrivers`
  replaces the removed `GitHubRest` service in Scient's server tests. GitCafe keeps
  Scient's `https` clone default. Forgejo's text names the Scient environment.
- **Thread shells:** `threadShellFromProjection` takes the caller's forge-aware
  `threadPullRequestsOf` (server or client copy), because `packages/shared` cannot
  depend on the forge packages; `ProjectionStore` exports a server-bound wrapper.
- **Search:** Scient's thread-search match schema spreads upstream's fields with a
  nullable `projectId`. A fork's inherited history stays searchable through a
  separate query merged before ranking. Ranking strips Scient's `scient/` and
  legacy `t3/` worktree branch prefixes as well as `t3code/`.
- **Migrations:** upstream's migration 69 (`ThreadMessageSearch`) is Scient's 73,
  as earlier alignments renumbered 67 and 68.
- **Read state:** upstream's `ThreadVisitWatermark`, which Scient removed on
  2026-10-19 because it marked unseen answers read, stays removed;
  `useAcknowledgeAnswer` remains the only visit writer that marks a thread read.
  Its new job, recording opens for search ranking, is kept: `ThreadOpenRecorder`,
  the Cmd+K pick and mobile send the thread's current watermark with
  `opened: true`, so the server counts the open and nothing is marked read. A test
  fails if an open is sent at the thread's latest activity.
- **Runtime guidance:** Scient's `link_pull_request` instructions take upstream's
  host-neutral wording and its delegated-child rule.
- **GitHub branch deletion:** Scient's gate keeps its test where upstream moved
  the credential test.
- **Workflows:** the managed-runtime publication guard covers the new forge
  definitions module and package.
