## Composition

- **Port scanner (#42155)** replaces Scient's earlier fix for the same macOS bug (`ps -E` read a
  platform binary's arguments as its environment). One Scient rule stays, marked: a process whose
  `ps -E` line adds nothing after its arguments is unreadable, so an Apple binary such as
  `/bin/bash` names no command.
- **Idle children on a parent's Stop (#41860)** get no Stop. Scient settles a stopped child's
  task after its Stop; a skipped child now gets that settlement through
  `Orchestrator.settleIdleDelegatedChild` when it still has an unsent result or a message-mode
  question left pending (an interrupted settlement), and nothing otherwise.
- **Task-folder teardown (#41986)**: T3 reads a folder's layout only when the request may run
  project commands. Scient's guard that keeps a folder with a teardown command out of automatic
  cleanup now reads the declared layout whenever the folder was laid out; whether the teardown
  runs still follows the request.
- **Restored update retry (#41964)**: T3 offers Retry in its update capsule, which Scient does not
  mount. Scient's other-updates circle rebuilds a restored row's target with T3's
  `resolveRestoredRetry`, shows the failure with its existing Retry, and settles a row whose
  server already runs that version without sending an update. The handoff also saves the update
  mechanism the user confirmed; a restored Retry is offered only while the server still offers it,
  and otherwise the row falls back to the ordinary Update, which asks again.
- **Deleted-thread snapshot (#41866)**: a deleted thread's snapshot is now missing. A resumed
  thread subscription that falls back to a snapshot reports that as
  `reason: "thread_not_found"` (optional, so older clients still decode the error), and a client
  holding cached detail retires the thread as on a delete event instead of keeping it as cached.
  T3's client has the same gap; a draft upstream report is kept with the alignment's review notes.
- **Queued-message edits (#41814)** carry T3's `modelSelection` beside Scient's `context` and
  skill names. **`/clear` in merge-back (#42114)** goes through
  `readHandoffItemsSinceContextBoundary`, which reads Scient's body-less history candidates.
- **Pi idle exit (#42196)** uses Scient's `bufferedWork` (T3's `pendingWake`), read before
  generation invalidation clears it.
- **Claude background sleep (#37875)** is T3's awaited-task restart path; Scient's ScheduleWakeup
  hold stays its own pending task.
- **Antigravity tool names (#41978)** check the proxied call's title against Scient's `scient`
  server and `scient_*` tools. **Skill picker (#42191)**: Scient already names plugin skills
  `plugin:skill`, so T3's separate display name is not added.
- **Desktop re-download (#42035)** keeps Scient's rule that the consented version stays binding.
- **ThreadVisitWatermark (#42084)** stays deleted: Scient's `useAcknowledgeAnswer` is the only
  visit writer and already keeps a background window's answer unread.
- **Workflows**: mobile EAS workflows take T3's read-only top-level permissions (#41038) beside
  Scient's Expo variables; `release.yml` stays Scient's own, and T3's version-bump check asserts
  that Scient's release pushes nothing back. The mobile fingerprint workflows stay off.
- **Docs**: T3's trademark text applies to forks that keep T3's name; Scient's README,
  CONTRIBUTING, AGENTS and docs index stay its own. User docs take T3's new facts under Scient's
  names (workflow hook rate limit, secret references need provider management, workflow runs
  need the broadest mode).
- **Catalogs**: the 20 translation catalogs are a three-way merge restricted to the generated
  keys; T3's two new "T3 Code" messages name Scient, each locale's translation carried over.
- **Agent context**: T3's pull-request tool text grew 120 bytes (#41981, #41809); the budget
  records it under the `agent-context-increase` label.
