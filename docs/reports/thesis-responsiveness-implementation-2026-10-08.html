Visual responsiveness: implemented changes

Scalar LQG Communication Capacity · Windows · 8 October 2026

The complete Scient browser client opened a diagnostic copy of the thesis through an isolated backend. All 422 formulas rendered as reading previews. Math editing, menus, command completion, row splitting, undo, and page thumbnails were exercised using the production build.

This improves the measured thesis workflow. It does not establish that Scient can never freeze, close the original macOS incident, or verify the native Electron shell. The final typing p95 remains above the proposed 100 ms target, and opening/layout still contain long tasks.

Production before and after

Input is keydown to a subsequent animation frame plus task, a next-paint proxy. Each sequence has 25 samples. CPU below is renderer main-thread task time; it excludes the math worker. What changed

  • Inactive formulas use static MathLive markup, the existing fonts, document macros and colors. Full editors activate on pointer or keyboard entry and explicit insertion. Native caret, selection, structural commands, completion and undo remain in the editing path.
  • A single cancellable worker handles reading math. Startup has a 15-second deadline, each formula a 3-second deadline, and output a 2-million-character limit. A failed preview retains exact readable source and remains editable; other formulas continue. The idle worker is released after two seconds.
  • Shadow-root previews share a stylesheet, preventing prose CSS and source updates from invalidating their internal layout. A stable error-notice context avoids rerendering formulas solely because source changed.
  • Projection installation skips identical canvas content. Genuine replacements update the changed ProseMirror range while retaining unaffected node views, mapping selection, and preserving scrolling. Existing source-lineage and outside-edit recovery guards remain in place.
  • Math preview DOM work yields after paint and gives pending input priority. Pagination coalesces preview, font and resize bursts and retains composition and typing quiet intervals. Equation numbers and thumbnails work with previews as well as active fields.
  • Typing snapshots, delayed source checkpoints, and text/math/object-field journals check stored versions before writing or retiring recovery data. Stale writers preserve newer drafts. Storage failures report a recovery notice and keep live input available. These checks are synchronous, not atomic cross-window locking; workspace source-session saving remains authoritative.

Implementation notes · Original profiling report

Interaction and recovery checks

Mouse and touch first entry focused native math. For the checked inline formula, the preview and editor had identical measured dimensions and source. Menus retained selection; Ctrl+Enter split a row and undo restored it; command completion produced a braced math argument. Thumbnail snapshots had rendered math and zero live inputs, including after editing.

The simulated storage checks used isolated random keys, restored storage methods, and removed their diagnostic data. They verified rejection of newer-record overwrite/deletion, delayed checkpoint overwrite, quota failure reporting, and retention after failed deletion. This does not simulate every crash or native process failure.

Method and preservation

    

      

        Windows 11, Intel Core i7-10510U, 8 logical CPUs, approximately 16 GB RAM; headless Chromium
        full client at 1500 × 1000. New browser context and cleared browser cache for cold
        production opening; OS cache remained warm. Source was requested first, then Visual. The
        sequence typed “ Responsiveness capture.” at 60 ms nominal spacing, undid, scrolled,
        switched Source/Visual/PDF, closed/reopened, forced diagnostic GC, and reloaded with warm
        browser cache.
      

      

        CPU sampling at 1 ms, browser tracing with V8 GC, Long Tasks API, CDP heap/DOM/task metrics,
        and field lifecycle counters were retained. Captures ran without builds or heavy analysis in
        parallel. Other user applications remained running; run-to-run opening times varied. The
        earlier production implementation run measured 139 ms p95; the final build measured 127 ms.
        Neither is a multi-trial statistical guarantee.
      

      

        Product sources were frozen from a dirty working tree; concurrent changes and pre-existing
        source guards can contribute to the comparison. The final production build was verified to
        exclude the development React runtime. A syntax error in the diagnostic bridge caused one
        rebuild to fail; the corrected build and accepted captures succeeded.
      

      

      

        All owned profiling processes were stopped. No test suite was run, and nothing was committed
        or pushed. The original source files were only read; diagnostic edits were confined to and
        restored in the thesis copy.
